# Local token protection (experimental)

Final-profile builds encrypt remembered account data with AES-256-GCM; PBKDF2-HMAC-SHA256 (200,000 iterations), fresh system-generated salt and nonce, and authentication tag. The existing account.json filename is retained for atomic in-place migration, but its new contents are binary PVV1, not JSON. A strong local 12–64 character password is required when saving or restoring. Never reuse a Sony password. Lost password: forget the account and sign in again. The legacy file is replaced only after authenticating the staged encrypted file. Old copies/backups or flash remnants may still exist; rotate the Sony token if exposure is suspected.

All existing login methods remain available. Local HTTP is not encrypted and imported JSON is plaintext. Settings > Security and privacy > Encrypt and remove imported JSON explicitly requests deletion of the original import after successful vault save. Copies on other devices are not removed. No claim of protection against compromised firmware, runtime memory access or physical forensic recovery. Passwords remain in memory only during native keyboard and storage operations, not persisted. Streaming is unchanged.

Downgrading to a build without vault support requires a fresh sign-in; never export a decrypted account to downgrade. A cancelled migration preserves the original. Ordinary file deletion cannot guarantee erasure of flash remnants. PBKDF2 performance needs measurement on physical hardware.
