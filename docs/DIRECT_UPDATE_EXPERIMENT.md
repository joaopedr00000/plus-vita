# B5/B6 direct updater experiment (not a release)
Based on VitaDB Downloader's self-update flow (source/main.cpp, app0 unmount and LoadExec), independently implemented for VitaPlus. No additional plugin required by the code; whether the firmware permits rename and LoadExec after unmount needs physical verification.

Install B5 manually from Actions. Download the paired B6 artifact; copy its VPK to ux0:Downloads/VitaPlus-update.vpk (do not overwrite unrelated files), and its SHA256SUMS.txt to ux0:Downloads/VitaPlus-B6-SHA256SUMS.txt. Verify the checksum against the Actions download independently. Select Beta and Check for updates, then Install verified update. The explicit Install and reopen manually option uses the original helper. All other versions use the original helper. B6 is a private test target, not a new public release.

The direct test checks the full extracted VPK, verifies that every packaged resource other than eboot.bin and param.sfo is byte-identical to the installed resource, and backs up both live files in ux0:data/VitaPlus/DirectUpdate. It writes a journal before touching live files and verifies checksums. After all UI workers and display shut down it unmounts app0 and attempts same-volume rename replacement (never unlinks live files to force a rename), verifies both files and requests LoadExec. Returned LoadExec failure triggers rollback. B5 startup can recover an interrupted transaction when the old executable still starts. B6 confirms after display initialization. Backup and test VPK are retained for recovery; direct path refuses a second transaction until manual cleanup. If firmware prevents rename, resource comparison fails, or a backup is already present, choose the helper; if direct preparation fails it falls back to the helper automatically. If the system cannot boot either executable, use VitaShell to reinstall the known-good B5 VPK, without uninstalling the app. No guarantee of atomicity across two files or recovery from power loss; system app database metadata may need normal VPK promotion. This is deliberately limited to a matching test pair; no stable/public release changes.
