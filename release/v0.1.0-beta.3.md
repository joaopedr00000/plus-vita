# Plus-Vita Beta 3 — Adaptive Streaming
Experimental build based on Beta 2, preserving the PV3 QR protocol and manual server selection.
- Three allocation bitrate profiles: low latency 6 Mbps, balanced 10 Mbps, quality 15 Mbps (default). The selected rate is requested at allocation, not guaranteed. Native Takion congestion feedback remains unchanged. One reconnect after previously decoded video and a qualifying network error requests 20% less, on the same server. No invented in-session bitrate command.
- Adaptive video reordering 16–48 ms based on frame repair/expiry, with bounded IDR recovery on queue pressure, never submit broken dependent frames.
- Reusable decoder submission buffer; native direct RGBA8888 scanout preserved (RGB565 direct display not documented by VitaSDK).
- Adaptive audio prebuffer 50/60/80 ms, up to 110 ms after starvation, fade-in and bounded queue.
- Optional video performance HUD: displayed FPS, received payload kbps, allocation RTT, queue length, reorder wait, last decode time, expired frames and local resync count. Not end-to-end input lag or true RTP jitter.
- Independent 4ms input sampling and H.264 reference guard, FEC and existing PS3/PS4 routes retained.
Hardware tests required; PS5 gameplay and GTA VI remain unconfirmed. Localization and RGB565 GXM presentation are separate future work. Profile and HUD preferences are saved locally without credentials. Use the existing Beta 2 offline helper.

## Unsupported regions (experimental discovery)
Optional persistent US, Canada and Portugal locale hints in account setup and Settings. When the authenticated legacy store returns HTTP 404, use the unified Pylux PS5 discovery path rather than aborting immediately. The actual account country is retained; Pylux may rebase the locale on Sony's account region. This is not IP relocation, entitlement spoofing, or a guarantee of cloud access. PS Plus Premium, regional eligibility and the actual server authorization still apply. No unlisted datacenter is invented or automatically selected. On 401, 403 or network errors the fallback does not run. Restart or reconnect the account after changing the setting.

## File-free Sony browser sign-in
Two new setup actions: Sign in on Sony (email/passkey) and QR login / enter token (no files). Unique QR links point only to Sony; passwords and verification prompts stay on Sony's website. Type the NPSSO in the masked native IME; reuse the existing import validation without a JSON file. The encrypted optical pairing helper and JSON import remain optional. No direct password collection or official device-code authorization is claimed. Remembered credentials are still locally readable; use Remember Off to avoid app-managed storage.

## AstraPlay-inspired authentication convenience
AstraPlay's Android WebView can manage Sony cookies; its embedded HTTP relay still requires a copied NPSSO and forwards the token. Plus-Vita instead adds optional reverse optical scanning without a helper file or network relay. Raw codes are explicitly unencrypted, not device-bound, and require confirmation. The existing AES-256 authenticated optical mode remains available. Thanks to AstraPlay and Pylux contributors for the architectural references.

## Current Beta 3 login: AstraPlay-inspired local relay only
Supersedes the earlier QR and manual import modes described above. Scan the Vita's temporary LAN QR, sign in on Sony, copy/paste the NPSSO response in the page served directly by the Vita, confirm on Vita. No companion file, public relay or Vita camera needed. Local HTTP is explicitly unencrypted. Private same-subnet access, unique session secret, three-minute expiry, one-time submission, and strict request validation. Remember is optional; existing saved accounts can restore, legacy import files are not automatically read. No claim of native Portal authentication. Credit to AstraPlay contributors for the embedded relay design.

## Sony connectivity and localization
Sony authorization errors now distinguish authorization, session and store stages; DNS, connection, timeout and TLS failures have safe numeric codes. Up to eight IPv4 addresses from normal DNS resolution are passed to curl and safe GETs may retry DNS/connect once. TLS verification remains enabled. No hardware reproduction yet.
Settings now includes a persistent Language choice for 19 GreenVita locales. Translated common menu labels, screen titles and sign-in instructions (58 strings per locale); dynamic diagnostics, game metadata, local browser page, some controls and other detailed text remain English. CJK glyph coverage and Arabic shaping/RTL require device validation; this is an initial UI localization pass, not a complete translation.

## TLS compatibility follow-up
A device report confirmed E16 on Sony authorization. The transport now explicitly verifies certificates and hostnames, uses HTTP/1.1 and TLS 1.2 or newer, loads the bundled public CA store through the application file API into libcurl's CA blob when supported, and retries safe GET requests with TLS 1.2 after handshake error 35 only. Certificate rejection is never bypassed. Per-call curl error codes differentiate handshake (35), certificate validation (60) and CA load (77), with Portuguese TLS messages. Physical-device resolution is unconfirmed.

## CA loader follow-up (E16/C77)
The build generates a canonical NUL-terminated PEM array from the same committed public CA resource and passes the entire array, including the terminator, as a static CA blob to libcurl. This removes runtime filesystem reads for supported TLS backends. Older unsupported blob backends retain the packaged file fallback. CA and hostname verification remain mandatory. Added host Mbed TLS parsing/count regression test. Hardware confirmation still required.

## C77 backend isolation
The previous build successfully parsed all 121 public roots in host Mbed TLS, but a Vita report still showed C77. The default VitaSDK container excludes curl-mbedtls and normally uses its OpenSSL curl package. Beta 3 CI now builds pinned curl 8.23.0 with the VitaSDK Mbed TLS backend in an isolated prefix and verifies the target archive before linking. Runtime checks reject an unexpected backend. The embedded trust store, certificate and hostname checks remain mandatory. This is a backend compatibility change, not proof of a successful Sony connection on hardware.
