# Private diagnostics hub
Independent HTTPS service for multiple applications. Public POST /v1/reports accepts strictly structured numeric diagnostics, no raw logs, text messages, credentials, account IDs, URLs or dumps. Owner-only GET /admin and /admin/report/:id use HTTP Basic over TLS, username owner and ADMIN_PASSWORD from host secret settings. Do not embed the admin password in any client. Do not expose the disk. The host may process IP addresses in infrastructure logs; the application does not store IPs in reports.
Client: show clear consent, send only after user chooses Send error report, POST JSON with Content-Length, verify TLS and hostname, no redirects, report 201 ID, retain local diagnostics on errors. Example: {"schema":1,"app":"vitaplus","version":"0.0.6-b1","events":[{"kind":"audio","code":-1,"elapsed_ms":500}],"metrics":{"audio_underruns":3}}
Events and metric identifiers in server.mjs define the v1 contract. For a new app add its slug and adapt its local diagnostics to this allowlist. Reports retained 30 days, 10,000 maximum, 64 KiB/request; rate limit is coarse and proxy sharing can reduce throughput. Public submissions are untrusted and app identity is not cryptographically verified. No client integration yet. Production needs HTTPS, persistent disk, backup/recovery policy, and monitoring. Run node --test server.test.mjs locally; render blueprint runs it during build. No changes to existing VitaPlus releases.
